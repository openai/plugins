# OpenDesign account models

Checked on 2026-11-15 against [OpenDesign source](https://github.com/nexu-io/open-design/tree/59e4f2ae85de7e7318a5e6bdcf3a34584c4b7582) and the command help of `@powerformer/vela-cli@0.1.10`. The CLI owns the account service contract; OpenMotion does not reproduce private authentication endpoints or bundle its binary.

The user signs in through **Settings → Account → Sign in with OpenDesign** and completes authorization in their browser. On first use, OpenMotion prepares the pinned connector in its private data directory. Credentials belong to this installation, are not copied from other apps, and are never returned to the Agent. Account models appear under provider ID `account`, alongside BYOK. A successful login establishes identity, not billing or generation acceptance; refresh subscription/usage for actual account balances.

Call `openmotion_media_use` with `action=inspect`, then `action=reference, provider=account`, then `action=models, provider=account, refresh=true`. Discovery uses the connector's remote model and media catalogues, including their enabled flags. Use only returned IDs and the provider's model parameter documentation; no model name or entitlement is guessed.

```json
{"action":"generate","provider":"account","projectId":"PROJECT_ID","requestId":"account-image-one","model":"CATALOGUE_MODEL_ID","modality":"image","prompt":"A ceramic cup","parameters":{}}
```

Image parameters supported by the connector boundary: `aspect_ratio`, `resolution`, `quality`, `size`. `aspect_ratio` and `resolution` must be given together as a pair the model publishes, `size` cannot be combined with them, and `quality` must be one of the model's values; the connector rejects other combinations before submission. Omit them to use the model default. Video uses `modality=video`, and accepts `ratio`, `resolution`, `duration`, `generate_audio`. Speech uses `modality=audio`, `mode=text-to-speech`, and requires `parameters.voice`. Music uses `modality=audio`, `mode=text-to-audio`, and accepts an optional whole-second `parameters.duration`; the catalogue publishes no duration range, so the account service decides which lengths it accepts. Unsupported parameters fail before submission.

Image editing: an image model returned with `supportsImageReference: true` (its catalogue entry publishes `edits` for this account) edits one input image. `openmotion_media_use` does not take input images; queue the edit with `openmotion_assets` `action=generate`, `model=account:CATALOGUE_MODEL_ID`, `modality=image` and exactly one pinned `references` entry (`assetId` and `versionId`). The image is snapshotted when queued and must be a PNG, JPEG or WebP under 20 MB; the original asset is not modified. Video first/last frames and video reference images are not supported through the account provider yet.

The service executes one `image gen`, `image edit` (with `--image` set to the snapshotted reference), `video gen`, `audio speech` or `audio music` command with `--model`, `--prompt`, `--no-wait`, `--json`. It saves the returned task_id, polls only that task through the corresponding `get`, and validates the downloaded file before importing it into the original project, or, for an `openmotion_assets` job, before adding it as a new library asset version. Poll with the tool that queued the job: `openmotion_media_use action=status` with the original projectId/jobId, or `openmotion_assets action=status` with the jobId; then place a library result with `openmotion_assets action=import_to_project`. Do not submit another task to check progress. Local requestId replay returns the original job.

Account session identity is captured when queuing. Signing out or switching identity prevents an old queued task from submitting under a new account. If `inspect` reports the `account` provider unavailable because the OpenDesign sign-in expired, ask the user to sign in again under **Settings → Account**. Account tasks queued before that fail without submission; resubmit them after the new sign-in. Failed CLI calls omit private stderr and cannot establish the exact remote error. Check account connectivity, available credits and original task history before retrying. Cancellation stops local work; it does not prove a remote cancellation or refund. Interrupted/uncertain paid requests are never automatically resubmitted or routed to another provider.
